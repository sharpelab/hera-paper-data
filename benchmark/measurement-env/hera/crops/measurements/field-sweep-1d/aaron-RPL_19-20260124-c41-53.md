The canonical "linecut in field" idiom in mature form. Cell 42 builds the AsyncStation, ramps to the target (n=0.465, D=1.000) operating point — 0.465 × 10¹² cm⁻², D = 1 V/nm — and runs the first 0 → 0.1 T sweep. Cells 43–52 are each one-line `s.sweep(mag.field, np.linspace(B_start, B_end, N), delay=0.5)` calls reusing the same Station, escalating the range outward each time. Cell 53 fits two sweeps in one cell (a ±1 T pair).

Pattern features:
- **Single Station, 13 sweeps off it.** No `s = sweep.AsyncStation(...)` rebuild between cells. The fp/plot list, the autorange callback, and the `s.add_comment` strings persist.
- **Range escalation chaining.** Each sweep starts where the previous ended (0 → 0.1, then 0.1 → −0.1, then −0.1 → 0.1, etc.), so the magnet never has to re-traverse — minimum wall-clock for the magnet leg. Only cell 53 breaks the chain (jumps from 0 → −0.7's end at −0.7 to start at −1).
- **Stale `add_comment` text.** `'MC6, Vsi = 48V, gate map in -100 mT'` — copy-pasted from a prior gatemap-in-field section even though this is a 1D sweep. The metadata snapshot via `grab_metadata()` is the only authoritative record of the current state. Recipe should call out: *don't parse gate state or field setpoint from the comment text alone; use metadata*.
- **`mag.field` ramp is commented out at cell start** (`# s.ramp(mag.field, 1.5)`) — Aaron is reusing the magnet's existing setpoint (0 T). The first cell 42 sweep then runs from 0 → 0.1 T as the very first field motion in this section.
- **Autorange callback is on for this section** (`s.register_run_before(autorange_sr830s_v2, (sr830_4, sr830s_2_autorange,))`) — different from the gatemap-in-field section above where it was commented out for ±B symmetrization purity. Here, sensitivity-tracking is more useful than pair-purity since these are escalating-range explorations, not symmetrization pairs.
- **Gate-current `fp` calls are commented out** — same as the gatemap-in-field cells 126/127/129, Aaron has decided gate-current monitoring is unnecessary mid-cooldown.
- **`sweep.AsyncStation` (modern API)** explicitly, vs. RPL_10's `async_station(mc)` wrapper.

This crop is the strongest example in the corpus of "build the Station once, sweep many times" — the full recipe in 12 cells, with cell 42 carrying all the setup overhead and cells 43–53 each being a single-line continuation.

Cells 55–57 (immediately after) pivot to gatemap form ("AH in the normal state" → `gatemap-in-field`), so this AH-spot-checks section ends naturally at cell 53.
