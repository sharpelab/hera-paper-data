# Gatemap in field

## What
A `gatemap` (axis-aligned in `(V_tg, V_bg)`) or `nD-map` (rasterized polygon in `(n, D)`) taken at fixed nonzero magnetic field. Same shape as the zero-field map, but with `mag.field` (or `yoko_mag.field`) ramped to the target value before the megasweep/multisweep starts and held throughout. Plots via `sharpelab_nb.plotting.plot_gatemap(file_path, file, nD=True)`. Used to look for AHC contrast (Hall voltage symmetry breaks at finite B), to suppress weak-localization, to map SC features that pin to specific (n, D) at finite field, and as one half of a ±B pair for downstream Hall symmetrization (cf. RPL_10 ana cells 86, 87, 106, 107 — the "Vanilla symmetrizing" pattern is the first analytical use of these maps).

## When
After a zero-field `gatemap` (or `nD-map`) has revealed at least one feature worth probing at finite field, and after the field source has been verified responsive (Yokogawa cache seeded after kernel restart, or AMI430 mag in operating mode). The `silicon-backgate-survey` and gate-validator recipes upstream are still hard dependencies; an `nD-map`-shape gatemap-in-field also requires the cap-ratio prerequisites of `nD-map`. For the ±B pair pattern, run the +B map and the −B map back-to-back in the same session: minimizes drift between the two and keeps file numbers adjacent for the analysis-side `(zsp + zsn)/2` symmetrization. If you don't already have a known-clean field setpoint: do a quick `field-sweep-1d` first to verify the magnet's setpoint matches the device's response.

## Why
Three reasons:
1. **AHC contrast** — at finite B, Hall channels pick up an antisymmetric signal whose ±B sum/difference cleanly separates Rxx from Rxy (the "AH contrib" recipe in the ana indexes). Zero-field maps see only Rxx; the symmetrization pipeline starts here.
2. **SC feature stability** — SC domes shift in (n, D) under B, and the relevant region of phase space at 100 mT or 1 T is not necessarily where the zero-field map predicts. A small set of `gatemap-in-field` runs at B ∈ {±100 mT, ±1 T} resolves this in 1–2 cooldown days.
3. **Trapped-flux check** — re-running the same map after the field has been ramped to a high value and back exposes whether the cryostat trapped flux. The map "should" look identical to before; if not, you have to retune `B_eff = 0` (cf. `aaron/RPL_19/20251220_measure.ipynb` cells 85+ "Checking trapped flux").

## Recipe
Build on `gatemap` (axis-aligned) or `nD-map` (polygon) — the only additions are the field ramp, a longer settle, and bookkeeping for the field setpoint:

1. Build `s = sweep.AsyncStation(mc)`. `s.add_comment('gatemap-in-field')` then optional structured tag identifying field and operating point: `s.add_comment(f'B = {B}T, Vsi = {V_si}V, gate map')`. **Watch out** — Aaron's RPL_19 sources copy-paste the prior section's comment text and frequently leave stale strings like `'... gate map in -100 mT'` even when the field setpoint is 1.5 T. Always also call `s.add_comment(grab_metadata())` so the magnet setpoint lands in metadata via the metadata snapshot, not just the comment string.
2. `s.ramp(mag.field, B)` (or `yoko_mag.field` if using the Yokogawa-controlled magnet path). For `|B| > 100 mT`, follow with `time.sleep(30)` or `interruptible_sleep(30)` — the magnet itself takes time to settle and the lock-ins need fresh time-constant windows after the ramp. For very high field (≥ 1 T), give it 60+ s.
3. Ramp the gates to the start of the sweep window: `s.ramp(k_tg.volt, V_tg_lo)`, `s.ramp(k_bg.volt, V_bg_lo)`. Then `s.ramp(sr830_1.amplitude, A)` to your standard excitation, and (if used) `s.ramp(bias_voltage.volt, 0)` to zero any DC bias.
4. `fp` and `plot` as in `gatemap` / `nD-map`. For finite-field maps with Hall channels, also `plot` `mag.field` vs each Hall lock-in's X so you see the trace evolve live.
5. (Optional) `s.register_run_before(autorange_sr830s_v2, (sr830_4, sr830s_2_autorange,))` if you've installed the v2 autorange that takes the current-channel SR830 explicitly. Skip if you want strictly identical sensitivity in the ±B pair (autorange differences between +B and −B will leak into the symmetrized output).
6. Run the sweep — `s.megasweep(k_tg.volt, ..., k_bg.volt, ..., slow_delay=3, fast_delay=1)` for the axis-aligned form (per `gatemap`) or rasterized polygon via `multisweep` (per `nD-map`).
7. **Don't park the magnet** at the end if you're about to do the −B counterpart — keep it ramped, just rebuild the AsyncStation for the next sweep. Otherwise: park gates (`k_bg.volt(0); k_tg.volt(0)`) and either `mag.field(0)` (if done with field for now) or leave the magnet at this setpoint.

If you're running the ±B pair: do `+|B|` first, then `−|B|` — the second run inherits a magnet that's already ramped, so the second sweep takes less wall-clock for the magnet leg. The two sweeps must use the **same** (V_tg, V_bg) grid for the analysis-side symmetrization to work without re-gridding.

## Next
- **You ran +B**: queue the −B counterpart immediately. Same polygon, same gates, fresh AsyncStation.
- **You have ±B in hand**: the analysis-side symmetrization (`Rxx_sym = (zsp + zsn)/2`, `Rxy_antisym = (zsp − zsn)/2`) lives ana-side; see RPL_10 ana cells 86, 87, 106, 107 and RPL_19 ana cells 103–107. The symmetrization recipe itself is deferred (cross-cutting analysis pattern; not a measurement recipe).
- **Saw an SC feature pin to a finite-field (n, D) point**: `field-sweep-1d` at that point to see how it evolves with B.
- **Asymmetric or hysteretic-looking gatemap**: `hysteresis-check` along an n-line through the suspect feature.
- **Want to know whether the magnet trapped flux**: re-run the zero-field `gatemap` and compare to your pre-field reference. (No dedicated trapped-flux recipe yet; deferred.)

`landau-fan` is the natural follow-up if the gatemap-in-field reveals quantum-oscillation-like patterns at the chosen field; deferred: `fraunhofer` if SC features visible.
