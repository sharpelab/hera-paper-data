(Cell 52: same as cell 50 with 201 fast-axis points and `slow_delay=10` — landau-fan-shaped, not strict 1D. Cell 53: same as 50/52 with 251 fast-axis points.)

This range mixes `field-sweep-1d` (cell 51 only) with `landau-fan` (cells 50, 52, 53). Cell 51 is the canonical strict-1D linecut-in-field at fixed (V_tg, V_bg):

- **Gate point picked from prior gatemap data**: `vtg, vbg = calculate_gate_voltages(-2.6, 0.31)` — n = −2.6 × 10¹² cm⁻², D = 0.31 V/nm, the center of the n-range probed by the surrounding 2D landau fan cells.
- **Field traversal**: 0 → 1 T over 1001 points, `delay=1` s — about 17 minutes wall-clock at this resolution. Density on B-axis is 1 mT.
- **`add_comment` carries (Vtg, Vbg) explicitly, in `comment_to_gates`-parseable form**: the trailing `(Vtg, Vbg) = ({vtg}, {vbg})` is the structured tag pattern. `comment_to_gates` (`sharpelab_nb.gates`) would parse this back to `(Vtg, Vbg)` for downstream analysis. This is the canonical example of Aaron's structured-tagging idiom — the recipe should reuse this pattern.
- **`s.ramp(mag.field, 0)` before the sweep** — important because cell 50 just ran a sweep that left the magnet at 0 T, but cell 51 explicitly resets it for clarity. The recipe should always do this.
- **`async_station(mc_4)` is rebuilt fresh** from cell 50 — Aaron rebuilds Stations at section boundaries even when reusing the same mc. This contrasts with RPL_19/20260124 c41–53 where the same Station drives 13 sweeps without rebuild.

The "resolution check" in the comment is Aaron's way of saying "this is the linecut version of the 2D fans I just took to confirm the oscillations are real" — the strict-1D sweep is faster per data point and reaches finer features than the 2D fan. The fact that Aaron uses both shapes within the same logical section is exactly the "don't trust the index, read the cells" lesson from the device-init batch.
