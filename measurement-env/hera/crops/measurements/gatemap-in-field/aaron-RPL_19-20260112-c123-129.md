from sweep import raster
import matplotlib.pyplot as plt

ns = np.array([0., 0.72, 2.5, 2.5, 0.])

The mature RPL_19 form: physical (n, D) polygon → `raster.rasterize` → `calculate_gate_voltages` (with the device-specific `dtg=17.25, dbg=25.5`) → preview scatter plot → multisweep. The preview plot in cell 125/128 is essential — confirms every rasterized point lies inside the gate validator window before the multisweep starts.

Notable bug: `s.add_comment('MC6, Vsi = 48V, gate map in -100 mT')` says "100 mT" but the actual `s.ramp(mag.field, 1.5)` is 1.5 T. The comment text is stale from a prior section; only the metadata snapshot via `s.add_comment(grab_metadata())` carries the real field. **Do not parse the field setpoint from the human-readable comment string** — use the metadata.

`s.fp(k_bg.curr)`, `s.fp(k_tg.curr)`, `s.fp(k_si.curr)` are all commented out — Aaron has decided gate-current monitoring is unnecessary at this stage of the cooldown (validators have been clean for weeks). Keep an eye on this — re-enabling the gate-current fp is cheap and recovers a leakage tripwire.

`s.plot(k_bg.volt, k_bg.curr)` is *still* present, even though `s.fp(k_bg.curr)` is off — this would silently fail in older `sweep` versions; in the current API it's tolerated because the lock-in plot tracks the available channels. Worth verifying this hasn't introduced a silent failure mode elsewhere.

Aaron's mature gatemap-in-field is structurally identical to `nd-gatemap` Flavor B (RPL_19/20251220 c69–76 if it had used `multisweep` instead of `megasweep`) plus the magnet ramp. That's a good pattern for a recipe to recommend: ramp the magnet visibly, settle, then build the AsyncStation.
